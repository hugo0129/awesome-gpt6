> Not just "what GPT-6 can do" — but **what problem it actually solved, and whether you can reuse it.**

Model capability sets the ceiling of what AI can do. What actually decides whether AI creates value is the **Case**.

## Why this project?

After every new model release, the internet fills up within days with:

- Feature breakdowns
- Benchmarks
- Prompt dumps
- Product reviews
- News takes

But the thing that actually matters is scattered everywhere:

> **How did one specific person use GPT-6 to do something that used to be hard?**

For example:

- A product manager taking GPT-6 from requirement analysis all the way to a prototype
- A developer letting GPT-6 carry a full software task end to end
- A founder using GPT-6 for market research, business analysis and product validation
- A teacher redesigning a course with GPT-6
- A designer going from concept to final visual delivery
- An ordinary person turning GPT-6 into a personal assistant
- A team wiring GPT-6 into a real business process

Those real cases are worth far more than another prompt collection.

That's what this repo is for: **a case library of GPT-6 in the real world.**

## What makes a case worth including?

We care about **cases, not prompts.**

A strong case should answer these seven questions:

1. **Problem** — What was the actual problem?
2. **Before** — How was it handled before?
3. **GPT-6** — Where exactly does GPT-6 come in?
4. **Workflow** — What does the full workflow look like?
5. **Result** — What came out at the end?
6. **Value** — How much time, money or new capability did it create?
7. **Reusable** — Can someone else reproduce it?

## Review Criteria

Cases with the following qualities get priority:

| Dimension  | Description           |
| ---------- | --------------------- |
| Real       | From a real task, not a demo built to show off AI |
| Useful     | Actually solves the problem |
| Reusable   | Others can reproduce it |
| Complete   | Includes a reasonably complete process |
| Insightful | Brings a new method or new understanding |
| Measurable | Ideally with time, cost or quality comparison |

In one line:

> **Not "looks impressive" — but "I can do this too after reading it."**
