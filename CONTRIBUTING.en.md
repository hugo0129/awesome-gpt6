# Contributing

[简体中文](CONTRIBUTING.md) | [English](CONTRIBUTING.en.md)

Thanks for writing a case down. **One reusable real-world case is worth more than a hundred prompts.**

---

## Three ways to contribute

| What you want to do | How | Rough time |
| --- | --- | --- |
| Recommend someone else's case | [Issue → Recommend a Case](https://github.com/hugo0129/awesome-gpt6/issues/new/choose) | 2 min |
| Submit a case you did yourself | Copy the [template](templates/case-template.en.md) → drop it in the right `cases/` folder → open a PR | 20 min |
| Fix, relink, translate | Open an issue or PR directly | anytime |

---

## Submitting a case (full walkthrough)

### 1. Check that it belongs here

If it hits three or more of these, it's worth writing:

| Dimension | Description |
| --- | --- |
| Real | From a real task, not a demo built to show off AI |
| Useful | Actually solves the problem |
| Reusable | Others can reproduce it after reading |
| Complete | Has a reasonably complete process, not just "I had GPT-6 do X" |
| Insightful | Brings a new method or new understanding |
| Measurable | Includes a before/after on time, cost or quality |

One-line standard: **not "looks impressive" — but "I can do this too after reading it."**

### 2. Pick a category

| Category | Folder |
| --- | --- |
| Thinking & Research | `cases/01-thinking-research/` |
| Coding | `cases/02-coding/` |
| Design | `cases/03-design/` |
| Writing & Content | `cases/04-writing-content/` |
| Data & Office | `cases/05-data-office/` |
| Agent & Automation | `cases/06-agent-automation/` |
| Business | `cases/07-business/` |
| Startup & OPC | `cases/08-startup-opc/` |
| Education | `cases/09-education/` |
| Industry | `cases/10-industry/` |

Not sure? Pick the stage where the case created the most value, and mention it in the PR — we'll move it if needed.

### 3. Create the file

```bash
git clone https://github.com/<your-id>/awesome-gpt6.git
cd awesome-gpt6
git checkout -b case/<short-english-name>
cp templates/case-template.en.md cases/02-coding/from-idea-to-webapp.md
```

Naming rules:

- English kebab-case, lowercase, hyphens: `from-idea-to-webapp.md`
- No Chinese filenames, spaces, or date prefixes
- One case per file — don't merge several

### 4. Write it

Template: [`templates/case-template.en.md`](templates/case-template.en.md) ([中文版](templates/case-template.md)).

**Add front matter at the top** so we can build an index and website later:

```yaml
---
title: From idea to production: one person shipped a web app with GPT-6
category: coding
tags: [GPT-6, Codex, Vibe Coding, Web App]
author: your-github-id
date: 2026-09-05
lang: en
source_url: https://example.com/original-post   # optional, original link
metrics:                                        # optional — fill it in if you have numbers, delete it if you don't
  time_before: 8h
  time_after: 45min
---
```

Set `lang` to `zh` or `en`. Add a one-line summary in the other language under the title:

```markdown
> 中文摘要：一个人用 GPT-6 在 45 分钟内完成了原本需要 8 小时的 Web App 开发。
```

### 5. Open the PR

```bash
git add cases/02-coding/from-idea-to-webapp.md
git commit -m "case(coding): add from-idea-to-webapp"
git push origin case/from-idea-to-webapp
```

Then open a PR titled `case(<category>): <case name>`.

The PR template asks three questions — that's it:

1. What problem does this case solve?
2. Can others reproduce it? (yes / partly / no, and why)
3. Any measurable results?

---

## Pre-submit checklist

- [ ] File is in the correct category folder
- [ ] Filename is English kebab-case
- [ ] Front matter filled in (`title` / `category` / `author` / `date` / `lang`)
- [ ] At least Problem, GPT-6 Workflow and Result are written out
- [ ] `metrics` filled in if you have real numbers — don't invent them if you don't
- [ ] Quoted or referenced material is credited with a link
- [ ] No API keys, internal URLs, client data or personal information

That last one is a hard rule: **cases must be real, but must not leak anything that shouldn't be public.** Redact sensitive details before writing.

---

## What gets rejected

- Result with no process ("I built a site with GPT-6, works great")
- Prompt dumps with no scenario or outcome
- Demos that were obviously generated by the model rather than actually done
- Copying someone else's content without attribution
- Promotional or ad content

Rejection usually just means the case is incomplete. Fill in the process and resubmit anytime.

---

## Just recommend, don't write

Totally fine. Go to [New Issue](https://github.com/hugo0129/awesome-gpt6/issues/new/choose) → **Recommend a Case** and fill in:

```text
Case Name:

Case URL:

Category:

What problem does it solve?

Why is it awesome?

Can others reproduce it?
```

We'll verify it and turn it into a proper case. You'll still be credited as a contributor.

## Other ways to help

- Add prompts, workflows or results to existing cases
- Translate Chinese cases into English summaries (and vice versa)
- Fix dead links, typos, miscategorization
- Propose new categories
- Help review PRs

---

## Code of conduct

Three rules: **be honest, be respectful, no ads.**

Describe honestly how far AI got and which parts still needed a human. Overclaiming damages the credibility of the whole repo — it's the one thing that gets a submission closed immediately.
